## Character animation fixture

`tests/fixtures/create_textured_character_fixture.py` writes ASCII FBX 7400 and a PNG
directly from the Python standard library, so no modelling application is required to
regenerate them. Run:

```
python3 tests/fixtures/create_textured_character_fixture.py
```

| File | Contents |
| --- | --- |
| `EpokSeamCharacter.fbx` | 4 bones (`Root` -> `Spine` -> `ArmL`/`ArmR`), 32 control points, 20 polygons (18 quads, one 5-gon, one triangle) -> 40 triangles, two referenced materials (`Body`, `Trim`), and 3 animation stacks `Clip00`/`Clip01`/`Clip02` baked at 30 fps. |
| `EpokManySequences.fbx` | Same rig and mesh, 30 animation stacks `Clip00`..`Clip29`, each 0.5 s, clip *k* driving the left arm to *k* x 10 degrees. Three of them use constant tracks. |
| `EpokSeamAtlas.png` | 64x32 (deliberately non-square) orientation atlas, 9 distinct colors. |

Deliberate properties, so import and cooking edge cases stay covered:

- **Per-corner texture coordinate seam.** Control point 0 carries two different
  coordinates: the torso front polygon assigns `(0, 0)` and the torso left polygon
  assigns `(1, 0)` in FBX space. Most other control points are seams as well.
- **Every atlas corner is used.** `(0,0)`, `(1,0)`, `(0,1)` and `(1,1)` all appear.
- **Mixed polygon sizes** exercise the triangulator: quads, one 5-gon and one triangle.
- **Both materials are referenced by faces**, so both become assets on import.
- `Clip00` is ~1 second of child-bone rotation, `Clip01` holds every bone still except a
  translating root, and `Clip02` is a single-sample clip (local start == local stop; the
  importer turns a zero duration into one frame). Every animated position stays within
  +/-2 m of the origin and every bone keeps scale 1.

Conventions: meters, Y up, front along -Z, one bone per control point (rigid skinning),
30 fps baked keys aligned to the importer's sample times, clip names are the animation
stack names.

Texture coordinate orientation: FBX stores `v` with the origin at the bottom-left while
PNG row 0 is the top, so the atlas coordinate is `[u, 1 - v]`. The generator's
`--sidecar <path>` flag writes a JSON description of the expected per-polygon control
points and both coordinate conventions, for importer tests.

The atlas is laid out so orientation is detectable: four solid quadrant colors (top-left
red, top-right blue, bottom-left green, bottom-right yellow), a dark strip along the top
row, and a unique single-pixel marker in each corner (white, magenta, cyan, purple
clockwise from the top-left).

`EpokManySequences.fbx` exists to cover the clip-count ceiling and will not import while
the per-model clip maximum is below 30.
