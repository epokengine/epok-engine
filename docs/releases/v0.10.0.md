# Epok Engine v0.10.0

This release adds a shared gameplay layer and game helpers. Six starter templates
now come in three authoring languages: C++, Blueprint, and Lua compiled to native
C++. Every template and language builds, plays on PSX and Native PC, and exports
as a standalone project.

## Starter templates in three languages

- Create Basic, Sample, Third Person, Platformer 2D, Dungeon or Dungeon Complete
  in **C++**, **Blueprint** or **Lua**. The chosen language owns the game rules;
  Lua is compiled ahead of time to native C++ for PSX.
- The three languages of each template share scenes, assets and behavior. The
  other two authoring systems remain available for extra classes.
- **Dungeon Complete** is now available in Blueprint and Lua, not only C++. This
  includes the combat, the economy, the shop, inventory, saving and the
  PocketStation transfer.

See [Starter classes and authoring language](../starter-templates.md) and
[Project templates](../projects.md).

## Gameplay base and helpers

- **Gameplay actions** route controller input through temporary contexts, so a
  player, a menu or a conversation can take shared buttons in turn. Third Person,
  Platformer 2D and Dungeon Complete use them.
- **World helpers** add examinable objects, dialogue NPCs, pickups, doors and
  switches as ordinary reflected classes. You can derive them in any of the three
  languages.
- **Dialogue widgets** are `UIActor` classes derived from `DialoguePresenter`.
  Conversation assets hold the lines, choices, conditions and actions.
- Characters and cameras are shared:
  - 2D and 3D character movement and animation;
  - camera rigs and projection helpers;
  - `HealthState` and `HealthLibrary` for bounded health arithmetic.
- **Projectiles and spatial queries.** `ProjectilePool3DComponent` and
  `SpatialQueryContextComponent` add pooled projectiles and shared 3D queries
  over the existing collision backend.

See [Gameplay actions](../gameplay-controls.md),

[Dialogue widgets](../dialogue-widgets.md), [Health](../health.md),
[Projectiles](../projectiles.md) and

## Runtime and tools

- Keep GPU field synchronization under PCSX-Redux. A missed VBlank no longer
  draws a frame into the wrong field. The pinned Nugget SDK carries the fix.
- Set `EPOK_MUTE_AUDIO=1` to silence PSX and Native PC Play output during
  automated runs. Gameplay and audio timing are unchanged.
- An acceptance runner, `tools/gameplay_helpers_acceptance.py`, covers all 18
  combinations. It checks generation, source ownership, reflection, build,
  Native and PSX Play, standalone export and resources.

## Compatibility and known limitations

- `VERSION`, the editor package and the shipped project descriptors advance to
  **0.10.0**. Open older projects through the Hub's confirmed upgrade, which
  backs up the descriptor.
- Every template passes build, Play, export and resource checks in all three
  languages. Some full-scenario evidence has not been recorded yet. This is
  missing test evidence; no functional failure is known:
  - Dungeon Complete: the PocketStation transfer has no recorded run with the
    acknowledgement interrupted. The runtime retries and times out after 5 s, and
    the game state does not credit ore twice.
  - The other five templates: authored-edit, baseline and full-coverage
    evidence.
- Performance:
  - Dungeon Complete exceeds the 25 ms frame target in some combat frames. The
    measured maximum is 26.6 to 29.4 ms depending on the language.
  - The Dungeon template also exceeds its 25 ms gate in some frames.
- The downloadable distribution remains Windows x64 Portable. Emulator checks do
  not establish physical-console timing.
